# whimsy/tools: landing lanes on one engine

One Mac, one engine (`~/Repos/whimsy/engine`). Every lane is tested as the
exact commit that will become `dev`, in the main checkout, as a ticket on a
first-come, first-served queue. Checks that take seconds run before anything
that takes minutes. The design and the W24 failures it answers are in
`~/Repos/whimsy-handoff/intake-w25/FABLE-PIPELINE.md`.

## Land a lane

```sh
npm run lane -- land w25-foo                 # lane/w25-foo onto dev
npm run lane -- land w25-foo --test browser_whimsy_menu_icons.js   # extra test files
npm run lane -- land w25-foo --message "Merge W25 foo: ..."
```

`lane.sh land` does, as one queue ticket:

1. refuses a dirty main checkout, or one not on `dev`;
2. merges the lane onto `dev` as a detached merge commit. The derived
   files merge through drivers, not as text: `src/**/whimsy-*.patch`
   (3-way merge of the patched source, then regenerated and `--check`ed),
   `prefs/whimsy/features.yaml` (by block, every pref keeps its value) and
   `whimsy/overlay.py` (both lanes' list entries). Generated files are
   regenerated by `overlay.py apply` so the commit is exact; a hook or
   hotfix the lane didn't commit is red here;
3. `precheck.py --since dev`: syntax, strings, XHTML, jar entries, every
   `whimsy-*.patch` applies after Zen's, every `chrome://`, `resource://`
   and `moz-src:///` URL names a packaged file, `overlay.py check`. It
   prints `BUILD: faster|backend|binaries|full`;
4. `npm run import`, which must leave no tracked file changed. It starts
   with `engine_prepare.py`, which puts back every engine file a patch or
   `src/` link of another branch (any ref, or the previous import) left
   behind, so lanes sharing the engine never build each other's patches;
   restored files that come back byte-identical keep their timestamps;
5. the build the change needs: `faster` (JS/CSS/FTL/XHTML, ~20 s),
   `backend` + `faster` (a moz.build changed), `binaries` + `faster`
   (native code or IDL), or full (surfer.json, configs, build patches);
6. eslint on the lane's JS (Prettier-only errors ignored);
7. the lane's tests: every `browser_whimsy_*.js` it changed or added, plus
   `--test` files, in three parallel harness runs (`test.sh`);
8. on green, `dev` fast-forwards to that commit and a full verify is queued
   at low priority (`verify-dev.sh`, one per branch at a time). On red,
   `dev` is untouched and the merge commit stays at `refs/tested/<lane>`.

Whatever happens, the main checkout is returned to `dev` with nothing left
behind (changes a step left are saved to the run folder and discarded).
The summary's first lines are `RESULT` and `REASON`; the run folder is
`~/Repos/whimsy/.surfer/lanes/<lane>/<time>/` (`summary.txt`, one log per
step). `.surfer/lanes/tickets.tsv` has one line per run for timing.

A red full verify writes `.surfer/verify/red-dev`; landings are refused
until a fix lane lands with `--fix` and the next verify is green.

## Test a lane without landing

```sh
npm run lane -- test w25-foo              # same steps, dev unchanged
npm run lane -- test w25-foo --dev w25-replay/dev   # against another branch
```

Workers in a worktree can run `python3 whimsy/precheck.py` there before
submitting (the engine is a link to the main checkout's), and
`python3 whimsy/tools/patchtools.py check` / `urlcheck.py` alone.

## Run tests by hand

```sh
whimsy/tools/queue.sh run -- whimsy/tools/test.sh browser_whimsy_home.js browser_whimsy_legacy.js
```

`test.sh` prints `RESULT`, one `REASON` per red chunk (crash with signal
and test file, timeout, assertion count, missing file, harness error) and,
after a crash, the native stack from `crash-stack.sh` (lldb in batch mode;
the dev build has no crash reporter). `crash-stack.sh FILE` runs one file
under lldb by itself.

## Verify dev

```sh
npm run verify:dev                 # full verify of dev, as a ticket
npm run verify:dev -- --mode quick
```

Builds what changed since the last recorded build, runs `whimsy/verify.sh`
(which now clears old logs first, so `failed.txt` describes this run), and
writes or removes `.surfer/verify/red-dev`.

## The queue

```sh
npm run queue -- status            # worker, lock, pending, running, recent
whimsy/tools/queue.sh run -- CMD   # run CMD with the engine to itself
whimsy/tools/lock.sh CMD           # the same; drop-in for wave13/lock.sh
```

Tickets are files in `/tmp/w13/queue`; one worker (started on demand)
runs them in order, normal priority before `--low`, and holds the old
mkdir lock (`/tmp/w13/engine.lock.d`) while a ticket runs, so scripts that
still use `lock.sh` from whimsy-handoff/wave13 are excluded too. Inside a
ticket, `queue.sh run` executes the command directly.

## Ship

```sh
whimsy/tools/ship.sh            # npm run ship as a queue ticket, after the gate
whimsy/tools/ship.sh --check    # the gate alone
```

The gate: main checkout on `dev` and clean, no `.surfer/verify/red-dev`,
and `verified.json` holds a green full verify (`all` or `gate`) of exactly
`dev`'s HEAD built from that commit (what `npm run promote` needs too).
W24 shipped a commit whose landing had never been verified; the ship's own
quick verify then found two real failures. `verify-dev.sh` after every
landing produces that record, so the usual path is: land, wait for the
verify ticket, ship. A plain `npm run ship` still works but does not check.

## Environment and git setup

`env.sh` carries the PATH (node, cargo, Homebrew) and the folders; every
tool sources it. `whimsy_git_setup` (run by `lane.sh`) installs the merge
drivers into the main repository's config and `info/attributes`, so they
apply to merges of any branch, including ones that predate `.gitattributes`.
Merging by hand in a worktree: after the merge, run `python3 whimsy/overlay.py
apply` and commit the regenerated files; `precheck.py` flags stale ones.

## Tests for the tooling

```sh
npm run test:tools                 # python3 -m unittest, no engine needed
```

`whimsy/tests/test_tools.py` covers the three merge drivers on fixture
repositories, the patch check, the URL resolver, the build-kind rules, the
log classifier on real W24 log excerpts (`whimsy/tests/fixtures/logs`), the
engine-overrides ledger and the queue's ordering.
