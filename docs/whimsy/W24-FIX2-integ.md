## Why the image fix retains native behavior

`engine/docshell/base/nsDocShellTreeOwner.cpp:852–896` ignores a prevented drop, but explicitly supports a page that cancelled only dragover: it checks the dropped link and invokes `RemoteDropLinks` for the unhandled drop. Accepting dragover therefore permits the DOM event checks without replacing or directly invoking native navigation. The target's drop listener only records primitive observations; it does not cancel the event. The original external-file case still uses the unclaimed-drop fixture, and the page-preventing-drop case still verifies that preventing the drop blocks native navigation.

The supplied p3 log reports 380/386 subtests passing for image drop; its six failures are exactly the three content-drop checks for each remote image case. Both cases finish without timing out on their new-image-tab promises. This matches Gecko's chrome-only dispatch behavior, rather than a failure to open the image.
